# 数据流向（知识库↔笔记↔系统层）

> 五层架构之间数据怎么流动——这是系统不"打架"的关键。

## 一、三通道

| 通道 | 内容 | 特点 |
|---|---|---|
| 知识库（固化层） | 锚点/宪法/方法论/技能 | 权威、持久、可检索、版本化 |
| 笔记（活跃层） | 待办/日志/每日记录 | 动态、追加、轻量 |
| 系统层记忆 | 人格/画像/长期记忆 | 每轮自动注入 |

## 二、数据流规则

```
① 写入方向
   对话产出 → 笔记层（先记下来）
   成熟内容 → 固化进知识库（从便签变档案）
   经验沉淀 → 任务档案 → 蒸馏 → 技能层

② 读取方向
   系统层（常驻）→ 每轮注入核心
   知识库（按需）→ AI 检索式加载（锚点定位）
   笔记层（动态）→ 待办/日志实时查
```

## 三、一致性铁律

1. **一个事实一个权威版本**：同一信息只存一处（改版走版本号，不复制多份）
2. **引用不写版本号**：索引指向"最新版"而不是"V2.3"（防引用断裂）
3. **回收站不索引**：归档文件不参与任何检索
4. **跨层同步**：知识库改版 → 检查笔记引用是否要同步更新

## 四、同步检查（每次变更后）

```
变更（新增/修改/移动文件）
    ↓
① 影响面：对哪些现有文件/机制有问题？
② 索引链：谁引用它？它引用谁？要更新吗？
③ 跨层联动：知识库↔笔记↔系统层要同步吗？
    ↓
检查通过才算收尾
```
