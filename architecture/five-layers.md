# 五层架构详解

> Self-Evolving Agent 的分层设计：为什么这样分、每层装什么、层与层怎么联动。

## 分层总览

| 层 | 名称 | 性质 | 核心职责 | 生命周期 |
|---|---|---|---|---|
| ① | 系统层 | 每轮自动注入 | 人格/画像/长期记忆 | 常驻 |
| ② | 知识库层 | 固化层 | 权威文档/方法论/技能库 | 持久 |
| ③ | 笔记层 | 活跃层 | 动态记录/待办/日志 | 追加式 |
| ④ | 技能层 | 可进化层 | Skill 定义/经验/蒸馏 | 版本迭代 |
| ⑤ | 边界层 | 守护层 | 隐私/主权/回滚 | 常驻 |

## ① 系统层（每次对话自动注入）

AI 每轮对话开始时自动加载的内容——它决定了 AI "是谁"、懂你多少。

```
soul（人格设定）     → AI 的语气/风格/行为规则
profile（用户画像）  → 你是谁（角色/习惯/偏好/边界）
memory（长期记忆）   → 正在进行的事（项目/决策/待办）
```

**设计关键**：这一层必须"轻"——只放每轮都需要的核心，其余按需加载（避免上下文爆炸）。

## ② 知识库层（固化层）

权威、持久、可检索的内容仓库。这是系统的"硬盘"。

```
anchor（锚点）       → 系统入口：恢复上下文的钥匙
constitution（宪法） → 最高行为准则（不可违反的铁律）
methodology（方法论）→ 可复用的方法（研究/写作/决策）
skill-library（技能库）→ 领域技能定义与版本
```

**设计关键**：
- 权威性：一个事实只有一个权威版本，改版走版本号
- 可检索：按关键词/标签可快速定位
- 只追加：历史不删除（回滚靠版本归档）

## ③ 笔记层（活跃层）

动态、追加式、轻量的记录层。这是系统的"便签本"。

```
todo（待办）        → 正在进行的事项（动态清单）
daily-log（日志）   → 每日记录（学习/工作/生活）
scratch（草稿）     → 临时想法（可丢弃）
```

**设计关键**：
- 追加为主（不重写历史）
- 与知识库层联动：活跃内容成熟后"固化"进知识库
- 待办完成即标记，不留死项

## ④ 技能层（可进化层）

系统"越用越强"的核心。每完成一批任务，技能升级一档。

```
skill 定义          → 触发条件/工作流/输入输出契约
experience（经验档案）→ 每次任务沉淀：问题/正确路径/错误路径
distillation（蒸馏） → 经验→方法论→回流技能
```

**设计关键**：
- 经验只追加不覆盖（历史可回溯）
- 正确/错误成对记录（防再犯）
- 蒸馏产物按领域分流（操作→SOP、质量→审查、工具→环境）

## ⑤ 边界层（守护层）

保证系统"安全可信"的底线。

```
privacy（隐私）     → 敏感信息隔离（什么不记录/不输出）
sovereignty（主权） → 决策权归属（AI 建议，人决策）
rollback（回滚）    → 系统可回退（改坏了能还原）
```

**设计关键**：
- 敏感信息分级（哪些进系统/哪些永不落库）
- AI 越权行为有红线（如替用户做决定）
- 每次变更可回溯（版本+归档）

## 层间联动（数据流向）

```
使用过程 → 笔记层记录 → 成熟内容固化 → 知识库层
任务完成 → 经验档案 → 满N条蒸馏 → 技能层升级
技能升级 → 下次任务更准 → 系统层记忆更新
边界层   → 全程守护（敏感信息不越层）
```

**一句话**：系统层是"前台"，知识库是"硬盘"，笔记是"便签"，技能层是"进化引擎"，边界层是"防火墙"。
