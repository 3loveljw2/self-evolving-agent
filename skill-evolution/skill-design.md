# Skill 设计与版本管理

> 技能层是系统"越用越强"的载体——怎么设计好 Skill、怎么管理版本。

## 一、什么是 Skill

Skill = 给 AI 的一段"专业能力包"：触发条件 + 工作流 + 参考知识 + 可执行脚本。让 AI 在特定场景下按成熟流程做事，而不是每次从零摸索。

## 二、好 Skill 的五要素

1. **触发条件清晰**：什么时候该用、什么时候不该用（写在 description 里）
2. **内容按需加载**：不把所有知识堆上下文，用 references 按需读取
3. **输入/输出契约**：明确"给它什么、它返回什么"
4. **可验证**：有 SOP、有验收标准、有示例
5. **可迭代**：版本号 + 经验回流机制

## 三、Skill 结构

```
skill-name/
├── SKILL.md          # 定义：触发条件/工作流/联动（入口）
├── references/       # 参考知识（方法论/SOP/示例）
└── scripts/          # 可执行脚本（如需要）
```

## 四、版本管理（回滚保证）

```
V1.0 → 使用 → 发现问题 → V1.1（修订）→ 旧版归档（可回滚）
        ↓
   每次修订记录：改了什么/为什么
```

- 版本号只在文件标题出现（引用不写版本号，取最新）
- 旧版归档不删除（回滚随时可还原）
- 重大变更先给方案，用户确认后执行

## 五、经验回流（Skill 自进化）

```
使用 Skill → 任务记录 → 经验档案
    ↓
满 N 条 → 蒸馏 → 提炼共性 → 更新 Skill 版本 +1
```

这就是"越用越强"的实现：Skill 每蒸馏一轮，就吸收一批真实踩坑经验。
