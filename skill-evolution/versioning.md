# 版本管理与回滚

> 系统可回滚是信任的底线：改坏了能还原，才敢放心迭代。

## 一、版本号规则

- 版本号格式：V大.小（V1.0 → V1.1 修订 → V2.0 大改）
- 版本号出现在：文件自身标题、蒸馏报告、锚点版本历史区
- 引用规则：索引/引用只写「标题+位置」不写版本号（检索取最新版）——避免引用断裂

## 二、归档机制

| 状态 | 位置 | 说明 |
|---|---|---|
| 当前权威版 | 原位 | 系统加载它 |
| 旧版本 | 归档区/回收站 | 不参与索引，可手动找回 |
| 废弃测试 | 回收站 | 用户定期清理 |

## 三、回滚流程

1. 发现系统异常/改错 → 定位问题版本
2. 从归档找回旧版（或 git checkout 历史 commit）
3. 恢复为权威版 → 验证
4. 记录回滚原因（经验档案）

## 四、git 配合（推荐）

如果系统文件用 git 管理：
- 每次修改 = 一个 commit（信息写清楚改了什么）
- 回滚 = `git revert` 或 `git checkout`
- 分支 = 实验新功能不破坏稳定版

## 五、铁律

- **重大变更先备份**（改前先确认旧版可恢复）
- **一次改一处，验证一处**（别一次改一堆然后一起炸）
- **改坏不硬扛**：立即回滚，回滚后总结经验
