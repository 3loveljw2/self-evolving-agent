# 经验蒸馏机制详解

> 自我进化的引擎：让系统的技能每完成一批任务就"升级"一档。

## 一、为什么需要蒸馏

AI 使用过程中每次任务都会遇到新问题（渲染出错、路径失效、难度偏差、工具坑）。如果经验散落，下次还踩同样的坑；如果全堆在一起，会越来越乱。

**蒸馏 = 把零散经验提炼成可复用方法论，回流到技能本身。**

## 二、闭环流程

```
每次任务完成
    │
    ├─ ① 写任务记录（追加一条）：
    │     【任务】做了什么
    │     【问题】遇到了什么
    │     【正确路径】怎么解决的
    │     【错误路径】踩了什么坑
    │
    ▼
任务档案累积（每任务 1 条）
    │
    ├─ ② 满 N 条触发蒸馏：
    │     读全部档案 → 提炼共性规律 → 分类
    │     （操作类→SOP / 质量类→审查清单 / 工具类→环境文档）
    │
    ▼
蒸馏产物
    │
    ├─ ③ 合并进方法论：技能版本 +1（V1.0 → V1.1）
    │     完整版进技能库 + 版本号，旧版归档（可回滚）
    │
    ▼
技能更新
    │
    └─ ④ 下次任务直接用蒸馏后的版本 → 新经验继续累积
```

## 三、三条原则

1. **只追加不覆盖**：经验档案是流水账，只增不删（历史可回溯）
2. **正确/错误成对记录**：光记"怎么做对"不够，还要记"怎么做错"——错误路径是防再犯的关键
3. **产物分流**：蒸馏出的经验按性质进不同地方（操作→SOP、质量→审查标准、工具→环境文档），不堆一个文件

## 四、效果

- 每蒸馏一轮，技能"变强"一档：审查更严、踩坑更少、交付更快
- 10 轮后积累的是**真实踩坑经验**而非理论——这是系统最大的护城河
- 对个人用户：AI 越来越懂你的习惯、偏好、常见问题

## 五、任务记录模板

```markdown
# 任务记录-YYYYMMDD-第X项-简述.md
## 任务（做了什么）
## 遇到的问题
## 正确路径（怎么解决的）
## 错误路径（踩了什么坑，防再犯）
## 产出（交付了什么）
## 待办（还没做完的）
```
